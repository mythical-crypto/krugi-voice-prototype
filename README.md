# Круги — локальный голосовой администратор

**[Готовая Windows-сборка — Releases](https://github.com/mythical-crypto/krugi-voice-prototype/releases/latest)**

Скачайте в одну папку три файла из релиза: `START-Krugi.cmd`, `Krugi-Windows-x64.zip.001` и `Krugi-Windows-x64.zip.002`. Запустите `START-Krugi.cmd`: он проверит SHA-256 обеих частей, соберёт и распакует исходный ZIP, затем откроет приложение. Нужна Windows x64 и примерно 9 ГБ места для частей, ZIP и распакованной папки вместе. После подготовки работа локальная, интернет и API-ключи не нужны.

Две части нужны из-за ограничения GitHub Release: каждый файл должен быть меньше 2 ГиБ. Стандартная кнопка GitHub «Source code (zip)» скачивает исходники, без моделей и окружения. Для обычного запуска используйте файлы релиза. После работы нажмите `ОСТАНОВИТЬ.cmd` внутри распакованной папки `Krugi`; закрытие вкладки не завершает серверы.

[Подробная аналитика](ANALYSIS.md) · [Интерактивный отчёт](docs/krugi-agent-analysis.html) · [Проверки](QA.md)

Для передачи другому человеку подготовлена переносимая Windows x64-сборка. В ней уже есть Node, самостоятельный Python без venv, production-зависимости и модели. После полной распаковки запускается `ЗАПУСК.cmd`; открывается Edge или системный браузер. `ОСТАНОВИТЬ.cmd` завершает принадлежащие сборке процессы. При недоступном Vulkan модель запускается на CPU, также есть `ЗАПУСК НА ПРОЦЕССОРЕ.cmd`.

Сборка архива из подготовленного проекта: `tools/python/venv/Scripts/python.exe scripts/package-portable.py --archive runtime/Krugi-Windows-x64.zip`. Для повторной упаковки проверенной папки: добавьте `--archive-only --stage "путь к папке Krugi"`. В архив не попадают разговоры, журналы, кэши и PID-записи. Скрипт формирует SHA-256 манифест и проверяет CRC ZIP. Регрессионная проверка поставляемой сборки: её `tools/node/node.exe scripts/portable-smoke.cjs` при работающих службах; проверяются ASR, TTS, цена и реальная генерация Qwen.

Рабочий демонстрационный прототип для Windows. Светлана консультирует о гончарных занятиях, помогает выбрать программу и проверяет бонусы по подтверждённому телефону. Qwen, распознавание Vosk и синтез Piper RU выполняются на этом компьютере. API-ключи и внешние AI-сервисы не используются.

## Запуск

В готовой сборке инструменты и модели уже включены. Если вы работаете с исходниками, сначала подготовьте окружение по разделу ниже. Команды выполняются из корня проекта.

```powershell
.\start.ps1
```

Откройте **http://127.0.0.1:9150**, нажмите «Начать разговор» и разрешите микрофон. Работает непрерывное слушание с голосовыми ответами. Громкая речь перебивает воспроизведение; есть отдельная кнопка «Прервать ответ». Используйте наушники для более устойчивого диалога. Номер телефона можно продиктовать по одной цифре или напечатать. Светлана повторит его и дождётся «да» / «всё верно».

Запрос разрешения микрофона больше не обрывается через 12 секунд. Дождитесь разрешения браузера или отмените ожидание кнопкой «Завершить разговор». После подключения индикатор показывает входящий уровень звука; точная причина ошибки сохраняется в диагностике. Текстовый режим доступен отдельной кнопкой.

Остановка:

```powershell
.\stop.ps1
```

Скрипты работают в Windows PowerShell 5.1 и PowerShell 7. Если локальная политика блокирует запуск, используйте её разовое переопределение только для этого процесса:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\start.ps1
```

Процессы запускаются скрыто. Повторный старт переиспользует подтверждённые процессы. Чужие занятые порты не освобождаются. Остановка сверяет PID, путь, командную строку и время создания; завершает только собственные процессы и их подтверждённые дочерние процессы.

Адреса: интерфейс `127.0.0.1:9150`, NestJS `127.0.0.1:3150`, llama.cpp `127.0.0.1:8150`. Все три слушают только loopback. Во время разговора сетевые обращения ограничены локальными службами. Системные службы и автозапуск не создаются; кэши, временные файлы и журналы находятся в `runtime/`.

## Подготовка и проверки

Для подготовки из исходников нужен `uv.exe`: расположите его в `tools/python/uv.exe` либо используйте установленный `uv`. `setup.ps1` скачивает зафиксированные Node/Bun, модели, локальный Python и зависимости, затем собирает приложение. Все новые инструменты и кэши остаются в папке проекта. Для готовой сборки из Releases этот шаг не нужен.

Подготовка проверяет SHA-256 моделей и инструментов и использует зафиксированные зависимости:

```powershell
.\setup.ps1
.\tools\bun\bun.exe run verify
```

`verify` объединяет Prettier check, ESLint, TypeScript, TS unit-тесты, API/WebSocket-интеграцию, тесты AudioWorklet, Python unit-тесты и production build. API-тест выполняется в поставляемом Node, поскольку Bun 1.3.3 зависает при закрытии тестового Nest HTTP-сервера. Сам производственный сервер работает в Node.

При запущенном приложении доступны отдельные проверки настоящих моделей:

```powershell
.\tools\bun\bun.exe run test:models
.\tools\bun\bun.exe scripts/voice-evaluate.ts
```

Перед голосовым тестом завершите разговор в интерфейсе: одновременно доступна одна активная сессия. Тесты используют вымышленные данные и записанные синтетические реплики. Они не требуют физического микрофона. Подробные результаты и аудиофайлы сохраняются в `runtime/dialogue-report.json`, `runtime/e2e-voice-report.json`, `runtime/voice-report.json`, `runtime/voice-worker-report.json` и `runtime/voice-fixtures/`.

## Демонстрационные программы и клиенты

| Программа                                 | Участники | Продолжительность | Базовая цена    |
| ----------------------------------------- | --------- | ----------------- | --------------- |
| Индивидуальное занятие на гончарном круге | 1         | 90 минут          | 3 200 ₽         |
| Индивидуальная лепка                      | 1         | 90 минут          | 2 800 ₽         |
| Парное свидание                           | 2         | 120 минут         | 5 600 ₽ за пару |

Это справочная копия значений. Единственные источники цен и правил для приложения — `data/catalog.json` и `data/bonus-policy.json`. В `data/knowledge.json` находятся демонстрационные сведения о техниках, новичках, материалах, обжиге, подготовке и сроке готовности изделий. Материалы и обжиг включены; учебный срок готовности — 3–4 недели. Приложение только читает JSON, не изменяет его.

| Тестовый телефон | Баланс |
| ---------------- | ------ |
| +7 900 000-00-01 | 0      |
| +7 900 000-00-02 | 600    |
| +7 900 000-00-03 | 2 000  |

Один бонус равен одному рублю. Покрыть можно максимум 20% базовой цены, отдельной скидки за первый визит нет. Расчёт целыми рублями: `applied = min(balance, floor(basePrice × maxCoveragePercent / 100))`, `total = basePrice - applied`. Бонусы не списываются. Неизвестный клиент или отказ от телефона означает базовую цену и неподтверждённые бонусы. Смена клиента/услуги сбрасывает предыдущий расчёт.

Пример: «Хочу на гончарный круг, я впервые» → «+79000000002» → «да» → баланс 600, к оплате 2 600 ₽. Затем «Передумал, хочу парное свидание» → к оплате 5 000 ₽ за пару. С балансом 2 000 на круге применяются только 640 бонусов, к оплате 2 560 ₽.

## Устройство

- `apps/frontend/`: React 19 + Vite 6, AudioWorklet переводит сигнал в PCM16 mono 16 кГц. WebSocket передаёт звук серверу и получает PCM16 с частотой, указанной сервером (Piper: 22,05 кГц). Очередь воспроизведения очищается при перебивании; устаревшие `turnId` игнорируются.
- `apps/backend/`: NestJS 12, сессии, отмена запросов, ограниченный цикл функций, проверка аргументов Zod, поиск по тексту/синонимам. Денежные утверждения выводятся из расчёта, а не из свободного текста модели.
- `apps/voice/`: Python 3.12, независимые потоки ASR/TTS, JSONL через stdin/stdout; журналы идут отдельно.
- `packages/shared/`: контракты, схемы событий, телефон и чистый расчёт.
- `skills/`: четыре сценария. При старте модель знает только краткий каталог. Полные SKILL.md загружаются через `load_skill` по намерению.
- `data/`: вымышленные знания и клиенты. `tools/`: подпапка для каждого инструмента и моделей. `scripts/`: подготовка, сборка, запуск, остановка и проверки.

Allowlist агента: `load_skill`, `search_knowledge`, `lookup_customer`, `calculate_quote`. Доступа к shell, произвольным файлам, внешней сети и платежам у модели нет. Обязательные вызовы направляет диспетчер: Qwen формирует настоящие function calls, сервер проверяет аргументы и исполняет их. Поиск возвращает фрагменты с ID, без передачи всей базы в system prompt. Полные внутренние рассуждения не запрашиваются и не показываются. Диагностика показывает только функции, источники и длительности.

## Обновление голоса и логики

Типовые вопросы о стоимости и точные FAQ обслуживаются через проверенные функции и найденные фрагменты, без ожидания генерации LLM. Свободные консультации и выбор программы по-прежнему используют настоящую Qwen и её function calls. Ответ на общий вопрос о цене перечисляет все три программы, прежде чем просить выбрать услугу. Вопрос «меня слышно?» получает прямое подтверждение.

[Piper Python API](https://github.com/OHF-Voice/piper1-gpl/blob/main/docs/API_PYTHON.md), [русский голос Irina](https://huggingface.co/rhasspy/piper-voices/tree/e9ab671f2a0e50a701b34361136ba3e6a3a9eb0c/ru/ru_RU/irina/medium). Все новые файлы также находятся внутри проекта; внешние запросы во время разговора не нужны.

## Существенные ограничения

По умолчанию выбран русский Piper Irina: он лучше подходит для русских названий и цен. MOSS/Bella сохранён для сравнения и доступен при запуске worker с `KRUGI_TTS=moss`. Vosk small всё ещё ошибается в окончаниях, названиях и цифрах. Пропущенные цифры не восстанавливаются; для надёжной проверки бонусов остаётся поле ввода.

Браузерная проверка выполняется только во внутреннем браузере Codex. В повторной проверке разрешение было получено, а живые вопросы пользователя о стоимости появились в ASR. На них воспроизведена и исправлена ошибка ответов; точные распознанные формулировки добавлены в тесты. AEC, порог речи и фильтр эха предусмотрены, но смешанная речь, шум и динамики остаются зависимы от окружения. Короткие подтверждения не подавляются; явное перебивание открывает следующую реплику.

Прототип может неверно понять свободную формулировку или ошибиться в объяснении. При недостатке знаний требуется уточнение у администратора. Реальная телефония, адрес студии, расписание, бронирование, платежи, уведомления и списание бонусов не подключены. Доступна одна активная голосовая сессия.

Фактические замеры всей голосовой цепочки приведены в `QA.md`: медиана типовых FAQ после обновления — 0,812 с, свободная консультация с Qwen — около 3,3 с. Измерение заканчивается получением содержательного PCM, физическое аудиоустройство и очередь браузера в него не входят.

Сверка с исходным планом и матрица плановых/дополнительных диалогов — в `ANALYSIS.md`. В диагностике отмечено, кто инициировал функцию: модель или правило сценария. Непрямые пожелания дополнительно классифицирует Qwen; цены и бонусы вычисляет код. Проверка диалогов с настоящей моделью: `.\tools\bun\bun.exe run test:scenarios:real` при запущенном прототипе. Отчёт со всеми репликами и трассами: `runtime/reports/krugi-agent-analysis.html`.
